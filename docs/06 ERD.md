# Назначение

Данный документ содержит высокоуровневую **ER-диаграмму (Entity Relationship Diagram)** проекта.

Документ описывает основные сущности системы, связи между ними и правила организации модели данных.

ERD используется для:

- проектирования базы данных;
- разработки ORM-моделей;
- создания миграций;
- анализа зависимостей между модулями;
- понимания предметной области.

Данный документ не заменяет описание моделей отдельных модулей, а представляет общую структуру базы данных.

```
Subject

└── Topic

      ├── Theory

      │      └── TheoryBlock
```

# Типы связей

В проекте используются следующие виды отношений.

| Тип | Использование |
|------|---------------|
| One-to-One | Профиль пользователя, общий прогресс |
| One-to-Many | Предмет → Темы, Тема → Задания |
| Many-to-One | Задание принадлежит теме |
| Many-to-Many | Используется только при необходимости через промежуточные таблицы |

# Правила моделирования

При проектировании сущностей необходимо соблюдать следующие правила.

- каждая сущность принадлежит только одному модулю;
- каждая таблица имеет UUID в качестве первичного ключа;
- используются внешние ключи для поддержания целостности;
- обязательны поля `created_at` и `updated_at`;
- каскадное удаление используется только при наличии бизнес-необходимости;
- пользовательские данные по возможности удаляются через Soft Delete.

---

# Правила расширения

При добавлении новой сущности необходимо:

1. определить владельца (модуль);
2. определить связи с существующими сущностями;
3. описать ограничения целостности;
4. обновить ERD;
5. создать миграцию.

---

# Ограничения

ERD отражает только **логическую модель данных**.

Документ не описывает:

- SQLAlchemy-модели;
- миграции;
- индексы;
- оптимизацию запросов;
- реализацию репозиториев.

Эти аспекты документируются отдельно.

---

# Definition of Done

ERD считается актуальной, если:

- отражены все основные сущности системы;
- указаны связи между сущностями;
- каждая сущность принадлежит своему модулю;
- структура соответствует документации модулей;
- диаграмма обновляется при изменении модели данных;
- ERD используется как единый источник информации при проектировании базы данных.
