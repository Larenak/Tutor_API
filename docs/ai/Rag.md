# Назначение

Модуль **RAG (Retrieval-Augmented Generation)** отвечает за предоставление AI-компонентам платформы доступа к внешним знаниям и учебным материалам через механизм поиска релевантной информации перед генерацией ответа.

RAG является связующим слоем между образовательными данными системы и языковыми моделями.

Модуль позволяет AI:

- получать актуальную учебную информацию;
- использовать официальные материалы подготовки к ЕГЭ/ОГЭ;
- отвечать на основе проверенных источников;
- снижать количество некорректных ответов;
- объяснять темы с учётом контекста обучения.

---

# Цели

Основные цели модуля:

- повысить точность ответов AI;
- обеспечить использование структурированных знаний;
- отделить знания системы от AI-модели;
- предоставить AI доступ к большим объёмам учебных данных;
- сделать обновление знаний независимым от обновления модели.

---

# Ответственность

Модуль отвечает за:

- загрузку учебных материалов;
- подготовку документов для поиска;
- разделение документов на части (chunking);
- создание embeddings;
- хранение векторных представлений;
- поиск релевантной информации;
- передачу найденного контекста AI-агентам;
- управление источниками знаний.

---

# Не отвечает за

Модуль не отвечает за:

- генерацию финального ответа пользователю;
- выбор AI-агента;
- создание промптов;
- хранение пользовательского прогресса;
- проверку решений ученика;
- бизнес-логику обучения;
- обучение языковых моделей.

# Компоненты

## Document Loader

Компонент загрузки источников знаний.

Источники:

- теория по предметам;
- учебники;
- справочные материалы;
- критерии оценивания;
- решения задач;
- методические материалы.

---

## Document Processor

Отвечает за подготовку документов.

Выполняет:

- очистку текста;
- нормализацию формата;
- извлечение метаданных;
- подготовку к индексации.

---

## Chunking Engine

Разделяет документы на небольшие смысловые блоки.

Причина:

LLM не может эффективно работать с большими объёмами текста.

Пример:

```

Документ:

"Производная функции"

```
    ↓
```

Chunk 1:  
Определение производной

Chunk 2:  
Правила вычисления

Chunk 3:  
Примеры решения

```

---

## Embedding Service

Преобразует текст в числовые векторные представления.

Пример:

```

"Квадратное уравнение"

```
    ↓
```

[0.124, 0.532, 0.921 ...]

```

Используется для поиска похожей информации.

---

## Vector Database

Хранилище векторных представлений.

Отвечает за:

- хранение embeddings;
- быстрый поиск похожих данных;
- фильтрацию по метаданным.

Возможные решения:

- PostgreSQL + pgvector;
- специализированные vector databases.

---

## Retriever

Компонент поиска информации.

Получает:

```

User Query

```

Находит:

```

Relevant Knowledge Chunks

```

Использует:

- semantic search;
- similarity search;
- metadata filtering.

---

## Context Builder

Формирует контекст для AI.

Объединяет:

- запрос пользователя;
- найденные знания;
- профиль ученика;
- инструкции агента.

Пример:

```

System Prompt

Student Context

Retrieved Knowledge

User Question

````

---

# Input

RAG получает:

- запрос пользователя;
- тему;
- предмет;
- тип задачи;
- дополнительные фильтры.

Пример:

```json
{
  "query": "Объясни теорему Пифагора",
  "subject": "Математика",
  "topic": "Геометрия"
}
````

---

# Output

RAG возвращает:

- найденные документы;
    
- текстовые фрагменты;
    
- метаданные;
    
- релевантность.
    

Пример:

```json
{
  "context": [
    {
      "text": "Теорема Пифагора...",
      "source": "geometry.pdf",
      "score": 0.92
    }
  ]
}
```

# Knowledge Base

Источники знаний разделяются по категориям.

## Theory Knowledge

Теоретические материалы:

- определения;
    
- правила;
    
- формулы;
    
- объяснения.
    

---

## Task Knowledge

Материалы по заданиям:

- типы задач;
    
- методы решения;
    
- типичные ошибки.
    

---

## Exam Knowledge

Информация об экзаменах:

- структура ЕГЭ/ОГЭ;
    
- критерии проверки;
    
- требования ФИПИ.
    

---

# Context Management

RAG должен передавать AI только релевантную информацию.

Принципы:

- ограниченный размер контекста;
    
- приоритет качества над количеством;
    
- фильтрация нерелевантных данных;
    
- контроль источников.
    

---

# Retrieval Strategy

Используемые стратегии:

## Semantic Search

Поиск по смыслу.

Пример:

Запрос:

```
Как найти площадь треугольника?
```

Может найти:

```
Формула Герона
Высота треугольника
Площадь через основание
```

---

## Metadata Filtering

Фильтрация:

```
subject = mathematics

topic = geometry

exam = EGE
```

---

## Hybrid Search

Комбинация:

- keyword search;
    
- semantic search.

# Security

Необходимо:

- контролировать источники знаний;
    
- предотвращать загрузку вредоносных документов;
    
- ограничивать доступ к внутренним данным;
    
- проверять пользовательские запросы;
    
- защищать от RAG poisoning.
    

---

# Logging

Логируются:

- запрос поиска;
    
- найденные документы;
    
- score релевантности;
    
- время поиска;
    
- ошибки индексации.
    

Не логируются:

- персональные данные без необходимости;
    
- приватный пользовательский контекст.
    

---

# Evaluation

Качество RAG оценивается по:

- точности найденных документов;
    
- релевантности контекста;
    
- снижению ошибок AI;
    
- скорости поиска.
    

Метрики:

- Retrieval Precision;
    
- Retrieval Recall;
    
- Context Relevance;
    
- Answer Accuracy.
    

---

# Extensibility

Модуль должен позволять:

- подключать новые источники знаний;
    
- менять vector database;
    
- использовать разные embedding-модели;
    
- добавлять новые стратегии поиска;
    
- создавать предметные базы знаний.
    

---

# Definition of Done

Модуль считается реализованным, если:

- реализована загрузка документов;
    
- реализован процесс chunking;
    
- создана система embeddings;
    
- настроено векторное хранилище;
    
- реализован поиск контекста;
    
- AI-агенты могут использовать найденные знания;
    
- есть контроль качества поиска;
    
- настроено логирование.
