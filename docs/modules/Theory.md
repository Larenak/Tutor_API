# Назначение

Модуль **Theory** отвечает за хранение, управление и предоставление теоретических учебных материалов платформы.

Модуль является источником данных для образовательного контента и предоставляет другим модулям доступ к теории через внутренние сервисы приложения.

Theory отвечает за:

- учебные статьи;
- объяснения концепций;
- структурированные материалы;
- связанные медиа;
- версии материалов;
- метаданные теоретического контента.

Модуль связывает теоретические материалы с учебными темами из модуля **Topics**.

---

# Зона ответственности

Модуль отвечает за:

- создание теоретических материалов;
- хранение теории;
- редактирование материалов;
- публикацию материалов;
- управление версиями материалов;
- связь теории с темами;
- описание проверяемых навыков и учебных целей каждого раздела теории;
- связь разделов теории с заданиями на их непосредственную отработку;
- управление структурой учебного материала;
- хранение метаданных контента;
- предоставление теории другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- создание учебных тем;
- управление предметами;
- хранение экзаменационных задач;
- проверку решений;
- оценивание учеников;
- построение персонального плана обучения;
- генерацию AI-объяснений;
- отслеживание прогресса;
- аналитику обучения;
- авторизацию пользователей.

Эти функции находятся в других модулях.

---

# Ограничения

Модуль не должен:

- хранить данные пользователей;
- хранить прогресс изучения;
- обращаться напрямую к AI;
- создавать персональные рекомендации;
- проверять ответы учеников;
- изменять структуру тем;
- выполнять платежные операции;
- отправлять уведомления;
- обходить интерфейсы других модулей;
- создавать циклические зависимости.

# Компоненты

# Основные сущности

## TheoryMaterial

Основной объект теоретического материала.

Содержит:

- название;
- описание;
- тему;
- статус;
- тип материала;
- дату создания.

---

## TheorySection

Часть материала.

Используется для разделения большого материала и является минимальной единицей, с которой связываются задания на отработку теории.

Каждый раздел содержит:

- учебные цели;
- проверяемые навыки;
- правила, определения или методы;
- разобранные примеры;
- типичные ошибки;
- идентификаторы заданий, которые непосредственно проверяют этот материал.

Пример:

```

Квадратные уравнения

├── Определение

├── Формула

├── Примеры решения

└── Типичные ошибки

```

---

## TheoryVersion

Версия теоретического материала.

Используется для:

- истории изменений;
- обновления контента;
- отката изменений.

# Бизнес-правила

- Теоретический материал принадлежит одной теме.
- Материал не может существовать без Topic.
- После вступительной диагностики обучение по теме всегда начинается с опубликованной теории.
- Каждый раздел теории имеет хотя бы одну учебную цель и один проверяемый навык.
- Задания на первичную отработку должны быть явно связаны с конкретным TheorySection, а не только с Topic или номером экзамена.
- Экзаменационная практика по теме открывается после теории и заданий на её непосредственную отработку.
- Вступительный тест является единственным сценарием, в котором задания показываются до теории; его результаты используются только для диагностики.
- У материала может быть несколько версий.
- Только опубликованный материал доступен ученикам.
- Архивные материалы не используются в обучении.
- Каждая версия материала уникальна.
- Изменения опубликованного материала создают новую версию.

---

# Инварианты

- TheoryMaterial всегда имеет уникальный идентификатор.
- TheoryMaterial всегда связан с Topic.
- У материала всегда есть статус.
- Версия материала всегда уникальна.
- TheorySection принадлежит только одному материалу.
- Порядок секций внутри материала уникален.
- Опубликованный TheorySection содержит учебные цели и проверяемые навыки, достаточные для точного отбора заданий.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Теория связывается с Topics через ID.
- Учебные задания связываются с конкретным TheorySection и его проверяемыми навыками.
- Нельзя считать совпадение номера экзамена достаточным соответствием задания теории.
- AI получает теорию только через сервисный интерфейс.
- Все изменения контента проходят через Service.
- Изменения структуры БД сопровождаются миграциями.
