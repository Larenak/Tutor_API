# Назначение

Модуль **Tasks** отвечает за хранение, управление и предоставление учебных заданий платформы.

Модуль является источником данных об экзаменационных заданиях и предоставляет другим модулям информацию через внутренние сервисы приложения.

Tasks отвечает за:

- задания;
- варианты ответов;
- решения;
- критерии проверки;
- сложность;
- принадлежность к темам;
- метаданные заданий.

Модуль связывает задания с учебной структурой через модуль **Topics**.

---

# Зона ответственности

Модуль отвечает за:

- создание заданий;
- хранение заданий;
- редактирование заданий;
- публикацию заданий;
- управление версиями заданий;
- связь заданий с темами;
- хранение условий задач;
- хранение решений;
- хранение ответов;
- хранение критериев проверки;
- классификацию заданий;
- предоставление заданий другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- проверку пользователя во время решения;
- хранение истории решений;
- расчет прогресса ученика;
- построение персонального обучения;
- генерацию заданий через AI;
- объяснение решений AI;
- хранение теории;
- управление пользователями;
- аналитику обучения.

Эти функции находятся в других модулях.

---

# Ограничения

Модуль не должен:

- хранить пользовательские попытки;
- хранить статистику решения;
- изменять прогресс ученика;
- напрямую обращаться к AI;
- самостоятельно оценивать уровень ученика;
- хранить платежные данные;
- отправлять уведомления;
- изменять структуру тем;
- обходить интерфейсы других модулей;
- создавать циклические зависимости.

# Компоненты

## Router

Назначение:

HTTP API интерфейс модуля.

Ответственность:

- получение заданий;
- получение задания по ID;
- фильтрация заданий;
- управление заданиями администраторами.

- бизнес-логики;
- работы с БД.

---

Назначение:

Основной слой бизнес-логики.

Ответственность:

- подбор заданий по параметрам.

# Бизнес-правила

- Каждое задание принадлежит одной теме.
- Задание не существует без темы.
- Опубликованные задания доступны ученикам.
- Черновики доступны только редакторам.
- Изменение опубликованного задания создает новую версию.
- Каждое задание имеет тип экзамена.
- Каждое задание имеет уровень сложности.
- Ответ должен соответствовать типу задания.
- У задания может быть несколько версий.

---

# Инварианты

- Task всегда имеет уникальный идентификатор.
- Task всегда связан с Topic.
- Task всегда имеет тип.
- Task всегда имеет сложность.
- Task всегда имеет статус.
- Версия задания уникальна.
- Решение принадлежит только одному заданию.
- Ответ принадлежит только одному заданию.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Проверка решений ученика находится вне Tasks.
- AI взаимодействует через сервисный слой.
- Изменение структуры заданий сопровождается миграциями.
- Все события документируются.
