# Назначение

Модуль **Admin** отвечает за административное управление платформой.

Модуль предоставляет инструменты для управления системой, мониторинга состояния приложения, контроля контента и выполнения служебных операций.

Admin является внутренним модулем, предназначенным только для пользователей с административными правами.

Модуль покрывает:

- управление пользователями;
- управление образовательным контентом;
- управление настройками платформы;
- просмотр системной аналитики;
- управление ролями и правами;
- модерацию данных.

Admin существует для обеспечения контроля, поддержки и развития платформы.

---

# Зона ответственности

Модуль отвечает за:

- административную панель;
- проверку административных прав;
- выполнение служебных операций;
- управление системными настройками;
- управление ролями пользователей;
- модерацию контента;
- просмотр технической информации;
- аудит действий администраторов.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- авторизацию пользователей;
- хранение профилей пользователей;
- хранение учебного контента;
- обработку платежей;
- генерацию AI-ответов;
- расчёт прогресса;
- работу рейтингов.

Admin только предоставляет интерфейс управления другими модулями.

---

# Ограничения

Модуль не должен:

- дублировать бизнес-логику других модулей;
- напрямую изменять чужие таблицы базы данных;
- обходить публичные API модулей;
- предоставлять доступ без проверки прав;
- хранить данные доменов других модулей;
- создавать циклические зависимости.

---

# Архитектура

Admin является управляющим модулем, который взаимодействует с другими модулями через их интерфейсы.

Основной поток:

```

Administrator  
|  
v  
Admin Panel  
|  
v  
Admin Module  
|  
+--> Users  
|  
+--> Tasks  
|  
+--> Theory  
|  
+--> Payments  
|  
+--> Analytics


```

Пример:

```
Администратор удаляет пользователя  
|  
v  
Admin отправляет команду  
|  
v  
Users выполняет удаление  
|  
v  
Событие UserDeleted
```

# Компоненты

## Router

Назначение:

Предоставляет API административной панели.

Ответственность:

- административные endpoints;
- получение системной информации;
- выполнение административных команд.

Не содержит:

- бизнес-логику;
- проверку сложных правил.

---

## Service

Назначение:

Содержит административную бизнес-логику.

Ответственность:

- управление административными действиями;
- проверка операций;
- координация работы модулей;
- создание аудита.

Основные методы:

```

manage_user()

manage_content()

update_settings()

view_system_stats()

create_admin_action()
```

---

## Repository

Назначение:

Работа с административными данными.

Ответственность:

- хранение логов действий;
- получение настроек;
- работа с административными сущностями.

# Бизнес-правила

- Только пользователи с административными ролями имеют доступ.
- Все административные действия записываются.
- Опасные операции требуют подтверждения.
- Администратор не может повысить свои права самостоятельно.
- Изменения системных настроек должны быть отслеживаемыми.

---

# Инварианты

- Каждое действие администратора имеет автора.
- Каждое действие имеет время выполнения.
- Все административные операции проходят проверку прав.
- Административные права не могут быть выданы без соответствующей роли.
- История действий не изменяется.

# Правила разработки

- Admin не содержит бизнес-логику других модулей.
- Все операции выполняются через публичные интерфейсы модулей.

- Опасные операции должны иметь дополнительную защиту.
- Новые права требуют обновления Permission Catalog.
