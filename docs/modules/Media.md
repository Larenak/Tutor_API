# Назначение

Модуль **Media** отвечает за управление файлами и цифровыми ресурсами платформы.

Модуль является единым слоем хранения и доступа к медиафайлам, которые используются другими модулями системы.

Media покрывает работу с:

- изображениями;
- файлами заданий;
- учебными материалами;
- пользовательскими загрузками;
- вложениями;
- временными файлами обработки.

Модуль существует для того, чтобы остальные доменные модули не занимались прямым управлением файлами и взаимодействовали с единым файловым сервисом.

---

# Зона ответственности

Модуль отвечает за:

- загрузку файлов;
- хранение метаданных файлов;
- управление жизненным циклом файлов;
- выдачу доступа к файлам;
- удаление файлов;
- проверку типов и размеров файлов;
- интеграцию с объектным хранилищем;
- контроль доступа к медиа.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- обработку содержимого файлов;
- распознавание изображений;
- анализ учебных материалов;
- генерацию теории;
- решение заданий;
- управление пользователями.

Примеры:

OCR использует Media для получения изображения, но не является частью Media.

AI использует Media для доступа к файлам, но не управляет их хранением.

---

# Ограничения

Модуль не должен:

- содержать бизнес-логику других доменов;
- анализировать содержимое файлов;
- хранить пользовательские профили;
- хранить учебные сущности;
- напрямую изменять данные других модулей;
- предоставлять неограниченный доступ к файлам;
- создавать циклические зависимости.

```

|

```

# Компоненты

## Router

Назначение:

Предоставляет API для работы с файлами.

Ответственность:

- загрузка файлов;
- получение информации о файле;
- удаление файла;
- получение ссылки доступа.

Не содержит:

- работу с хранилищем напрямую;
- бизнес-правила.

---

## Service

Назначение:

Управление жизненным циклом файлов.

Ответственность:

- загрузка файлов;
- создание метаданных;
- удаление;
- генерация временных ссылок;
- управление состоянием файла.

Основные методы:

```

upload_file()

delete_file()

get_file_url()

validate_file()

```

---

## Repository

Назначение:

Работа с метаданными файлов в базе данных.

Ответственность:

- создание записей;
- поиск файлов;
- обновление информации;
- удаление метаданных.

---

## Schemas

Назначение:

Описание DTO.

Содержит:

- загрузку файла;
- информацию о файле;
- ответы API.

---

## Models

Назначение:

Описание ORM моделей.

Содержит:

- MediaAsset;
- FileAccess;
- StorageObject.

---

## Validators

Назначение:

Проверка файлов.

Ответственность:

- проверка расширения;
- проверка MIME-типа;
- ограничение размера;
- проверка безопасности.

---

## Permissions

Назначение:

Контроль доступа к файлам.

Ответственность:

- пользователь имеет доступ только к своим файлам;
- публичные файлы доступны по правилам;
- администратор имеет расширенные права.

# Основные сущности

## MediaAsset

Основная сущность файла.

Содержит:

- владельца;
- тип файла;
- размер;
- путь хранения;
- статус.

Пример:

```

image_123.png  
task_photo.jpg  
theory_video.mp4

```

---

## StorageObject

Физическое представление файла в хранилище.

Содержит:

- bucket;
- path;
- provider.

---

## FileAccess

Информация о доступе.

Содержит:

- кто имеет доступ;
- срок действия;
- тип доступа.

# Бизнес-правила

- Каждый файл имеет владельца.
- Все файлы проходят проверку перед сохранением.
- Удаление файла не должно нарушать связи с другими модулями.
- Временные файлы должны автоматически очищаться.
- Доступ к файлам контролируется через Media.

---

# Инварианты

- MediaAsset всегда имеет уникальный идентификатор.
- MediaAsset всегда имеет путь хранения.
- Размер файла не может быть отрицательным.
- Пользователь не может получить чужой приватный файл.
- Удалённый файл не должен быть доступен.

# Правила разработки

- Router не содержит бизнес-логики.
- Service управляет жизненным циклом файлов.
- Repository работает только с метаданными.
- Работа с хранилищем скрыта за интерфейсом.
- Новые типы файлов документируются.
- Изменение событий требует обновления Event Catalog.
