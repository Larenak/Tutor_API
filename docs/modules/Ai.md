# Назначение

Модуль **AI** отвечает за интеграцию искусственного интеллекта в образовательную платформу.

Модуль предоставляет интеллектуальные возможности:

- объяснение учебного материала;
- анализ ошибок пользователя;
- генерация рекомендаций;
- персонализация обучения;
- помощь в решении задач;
- генерация учебного контента;
- построение AI-контекста пользователя.

AI является интеллектуальным слоем системы и не является владельцем образовательных данных.

Модуль использует данные из:

- Topics;
- Theory;
- Tasks;
- Progress;
- Roadmap.

---

# Зона ответственности

Модуль отвечает за:

- интеграцию с LLM-провайдерами;
- управление AI-запросами;
- работу с промптами;
- управление AI-агентами;
- работу RAG-системы;
- построение контекста пользователя;
- генерацию объяснений;
- анализ ошибок;
- генерацию рекомендаций;
- управление AI-сессиями;
- контроль качества AI-ответов.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- хранение пользователей;
- хранение теории;
- хранение заданий;
- хранение прогресса;
- создание roadmap;
- изменение данных других модулей;
- авторизацию;
- оплату;
- управление подписками.

AI не является источником истины.

Источниками данных являются:

- Users;
- Topics;
- Theory;
- Tasks;
- Progress;
- Roadmap.

---

# Ограничения

Модуль не должен:

- напрямую изменять данные других модулей;
- хранить основную бизнес-информацию;
- принимать решения без контекста;
- обходить сервисы других модулей;
- хранить персональные данные без необходимости;
- отправлять запросы к AI-провайдерам без контроля;
- использовать неподтвержденные данные;
- создавать циклические зависимости.

# API / Интерфейсы

## Реализованный MVP-контур

Первая интеграция использует настраиваемый AI Provider и поддерживает как прямой
DeepSeek API, так и DeepSeek через OpenRouter. Ключ читается из `DEEPSEEK_API_KEY`
или `OPENROUTER_API_KEY`; без ключа основной учебный поток продолжает работать, а
AI API возвращает контролируемый `503`. Ключ `sk-or-*` в старой переменной
`DEEPSEEK_API_KEY` автоматически направляется в OpenRouter.

Реализованы интерфейсы:

```
GET  /api/v1/ai/status
POST /api/v1/ai/explain-theory
POST /api/v1/ai/hint
POST /api/v1/ai/analyze-error
```

Ограничения первого контура:

- объяснение строится только по разделу текущего roadmap-урока;
- подсказки доступны только для текущей задачи практики и имеют три уровня;
- подсказка не должна сообщать окончательный ответ;
- разбор ошибки запускается только для сохранённой неверной попытки пользователя;
- при коротком ответе без хода решения AI обязан сообщать об ограниченной уверенности;
- AI не изменяет Progress и Roadmap и не является источником правильного ответа;
- ответ модели проходит проверку структурированной Pydantic-схемой.
- OpenRouter выбирает провайдеров по throughput, сохраняет fallback и повторяет
  временные 429/5xx либо повреждённый JSON в пределах общего бюджета запроса;
- вопрос по теории не заменяется сохранённым старым ответом при ошибке;
- объяснение адаптируется к намерению вопроса и возвращает прямой ответ, правило,
  2–4 шага, новый пример, связанную ошибку и интерактивную самопроверку;
- ученик вводит ответ на самопроверку: первая ошибка открывает подсказку, вторая —
  эталон и короткий разбор. Дополнительный запрос к AI для проверки не требуется.

Переменные окружения:

```
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_SECONDS=30
OPENROUTER_API_KEY=
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_MODEL=deepseek/deepseek-v4-flash-0731
OPENROUTER_TIMEOUT_SECONDS=25
OPENROUTER_MAX_RETRIES=2
OPENROUTER_SITE_URL=http://127.0.0.1:8000
OPENROUTER_APP_NAME=AI Tutor
```

# Бизнес-правила

- AI всегда работает через контекст.
- AI не изменяет данные других модулей напрямую.
- Каждый запрос пользователя имеет тип.
- Каждый AI-ответ сохраняет информацию о версии промпта.
- AI-ответы могут быть кешированы.
- Источник знаний должен быть проверяемым.
- AI не заменяет бизнес-логику доменных модулей.

---

# Инварианты

- AIRequest всегда принадлежит пользователю.
- Каждый AIResponse связан с запросом.
- AI не существует без LLM-провайдера.
- Контекст запроса всегда ограничен.
- Версия промпта всегда сохраняется.
- AI не изменяет состояние обучения напрямую.

# Правила разработки

- Router не содержит AI-логики.
- Service управляет AI-сценариями.
- Prompt версии хранятся отдельно.
- AI не изменяет доменные данные напрямую.
- Все вызовы LLM проходят через единый слой.
- Контекст всегда собирается через Context Service.
- Новые агенты документируются.
