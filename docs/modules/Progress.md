# Назначение

Модуль **Progress** отвечает за хранение и управление прогрессом обучения пользователя на платформе.

Модуль является источником данных о текущем состоянии подготовки пользователя:

- изученные темы;
- выполненные задания;
- результаты практики;
- уровень освоения материала;
- слабые и сильные стороны пользователя.

Progress предоставляет другим модулям информацию о состоянии обучения через внутренние сервисы приложения.

Модуль является основой для:

- персонализации обучения;
- аналитики;
- AI-рекомендаций;
- адаптивного roadmap.

---

# Зона ответственности

Модуль отвечает за:

- хранение прогресса пользователя;
- отслеживание изучения тем;
- отслеживание выполнения заданий;
- хранение результатов попыток;
- расчет состояния освоения темы;
- хранение уровня уверенности пользователя;
- хранение истории обучения;
- предоставление данных другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- создание пользователей;
- хранение профиля пользователя;
- хранение тем;
- хранение заданий;
- проверку правильности ответа;
- генерацию AI-рекомендаций;
- построение roadmap;
- хранение теории;
- управление подписками;
- оплату.

Эти функции находятся в других модулях.

---

# Ограничения

Модуль не должен:

- изменять данные Users;
- изменять структуру Topics;
- изменять задания Tasks;
- самостоятельно проверять решения;
- самостоятельно генерировать рекомендации;
- обращаться напрямую к AI;
- хранить учебный контент;
- выполнять платежные операции;
- создавать циклические зависимости.

# Компоненты

## Router

Назначение:

HTTP API интерфейс модуля.

Ответственность:

- получение прогресса пользователя;

- получение состояния темы;
- административный просмотр прогресса.

- обработка событий обучения;
- агрегация результатов.

---

# Основные сущности

## UserProgress

Общий прогресс пользователя.

Содержит:

- пользователя;
- общий процент подготовки;
- количество выполненных заданий;
- количество изученных тем.

---

## TopicProgress

Прогресс пользователя по теме.

Содержит:

- тему;
- уровень освоения;
- статус изучения;
- количество попыток.

Пример:

```

Topic:  
Квадратные уравнения

Status:  
Completed

Mastery:  
85%

```

---

## TaskProgress

Результат выполнения задания.

Содержит:

- пользователя;
- задание;
- количество попыток;
- последний результат;
- дату выполнения.

---

## LearningHistory

История действий пользователя.

Содержит:

- событие;
- объект обучения;
- дату;
- результат.

# Бизнес-правила

- Каждый пользователь имеет один общий Progress.
- Прогресс темы существует только вместе с пользователем.
- Прогресс задания создается после первой попытки.
- Уровень освоения рассчитывается на основе результатов обучения.
- Прогресс нельзя изменить напрямую через API пользователя.
- История обучения не изменяется после создания.
- Удаление пользователя удаляет или анонимизирует прогресс.

---

# Инварианты

- UserProgress всегда принадлежит одному User.
- TopicProgress всегда связан с User и Topic.
- TaskProgress всегда связан с User и Task.
- Значение mastery находится в диапазоне 0-100.
- История обучения неизменяема.
- Один пользователь не может иметь несколько записей прогресса одной темы.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Progress не изменяет данные других модулей.
- Проверка решений находится в Practice.
- Все изменения состояния проходят через Service.
- Изменение структуры БД сопровождается миграциями.
