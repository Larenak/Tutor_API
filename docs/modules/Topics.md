# Назначение

Модуль **Topics** отвечает за управление структурой учебных тем платформы.

Модуль является источником данных о предметной структуре подготовки:

- темы;
- подтемы;
- иерархия знаний;
- связи между темами;
- сложность тем;
- метаданные подготовки.

Topics используется другими образовательными модулями для построения учебного процесса.

Модуль является связующим слоем между предметами (**Subjects**) и образовательным контентом:

- Theory;
- Tasks;
- Roadmap;
- Progress;
- AI.

---

# Зона ответственности

Модуль отвечает за:

- создание учебных тем;
- хранение структуры тем;
- управление иерархией тем;
- связь тем с предметами;
- хранение метаданных тем;
- управление уровнем сложности;
- управление порядком изучения;
- хранение зависимостей между темами;
- предоставление информации о темах другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- хранение теоретических материалов;
- хранение задач;
- проверку решений;
- генерацию AI-рекомендаций;
- построение персонального roadmap;
- отслеживание прогресса пользователя;
- аналитику обучения;
- результаты экзаменов;
- авторизацию пользователей.

Эти функции находятся в других модулях.

---

# Ограничения

Модуль не должен:

- содержать учебный контент;
- обращаться напрямую к AI;
- хранить пользовательские данные;
- хранить историю обучения;
- выполнять проверку задач;
- строить персональные планы подготовки;
- изменять данные других модулей;
- обходить интерфейсы других модулей;
- создавать циклические зависимости.

# Компоненты

## Router

Назначение:

HTTP API интерфейс модуля.

Ответственность:

- получение списка тем;
- получение информации о теме;
- создание и изменение тем администраторами;
- управление структурой через API.

Не содержит:

- бизнес-логики;
- прямой работы с БД.

---

## Service

Назначение:

Основная бизнес-логика управления темами.

Ответственность:

- создание тем;
- изменение структуры;
- проверка связей;
- управление сложностью;
- управление зависимостями между темами.

---

## Repository

Назначение:

Работа с базой данных.

Ответственность:

- получение тем;
- сохранение изменений;
- поиск по предмету;
- получение дерева тем.

Не содержит:

- бизнес-правил.

---

## Schemas

Назначение:

Pydantic DTO для API.

Содержит:

- создание темы;
- обновление темы;
- чтение темы;
- дерево тем.

---

## Models

Назначение:

SQLAlchemy модели.

Основные модели:

- Topic;
- TopicDependency.

---

## Validators

Назначение:

Проверка данных.

Проверяет:

- корректность названия;

- корректность сложности;
- корректность порядка изучения.

## Permissions

Назначение:

Проверяет:

# Основные сущности

## Topic

Основная сущность учебной темы.

Содержит:

- идентификатор;
- название;
- описание;
- предмет;
- родительскую тему;
- уровень сложности;
- порядок изучения;
- статус.

## TopicDependency

Связь зависимости между темами.

Используется для описания:

- какие знания нужны перед изучением темы;
- какие темы являются связанными.

# Бизнес-правила

- Каждая тема принадлежит одному предмету.
- Тема может иметь только одну родительскую тему.
- Корневая тема не имеет родителя.
- У темы не может быть родителем сама себя.
- Циклические зависимости запрещены.
- Порядок изучения темы должен быть уникальным внутри родителя.
- Удаление темы возможно только если нет активных зависимостей.
- Тема не может существовать без предмета.

---

# Инварианты

- Topic всегда имеет уникальный идентификатор.
- Topic всегда принадлежит Subject.
- Topic не может ссылаться сама на себя.
- В дереве тем отсутствуют циклы.
- Dependency не может связывать тему саму с собой.
- Каждая тема имеет уровень сложности.
- Каждая тема имеет статус.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Изменение структуры тем сопровождается миграцией.
- Все события документируются.
- AI не изменяет темы напрямую.
- Все изменения проходят через Service.
