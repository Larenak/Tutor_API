# Назначение

Модуль **OCR** отвечает за распознавание и преобразование изображений с заданиями, решениями и учебными материалами в структурированные цифровые данные.

Модуль является связующим звеном между пользовательским вводом через изображения и внутренними образовательными модулями системы.

OCR существует для того, чтобы пользователь мог:

- загрузить фотографию задания ЕГЭ/ОГЭ;
- получить распознанный текст;
- автоматически определить структуру задания;
- передать данные в AI-модуль для анализа и решения.

Модуль покрывает область обработки изображений и извлечения информации из визуальных данных.

---

# Зона ответственности

Модуль отвечает за:

- загрузку изображений для распознавания;
- хранение информации о процессах OCR;
- обработку изображений;
- вызов OCR-движков;
- извлечение текста из изображений;
- базовую очистку и нормализацию распознанных данных;
- определение качества распознавания;
- передачу результата другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- решение учебных задач;
- объяснение теории;
- генерацию ответов ученику;
- определение уровня знаний пользователя;
- создание персонального плана подготовки;
- хранение пользовательского прогресса;
- хранение учебных материалов.

Эти задачи принадлежат:

- AI модулю;
- Theory модулю;
- Tasks модулю;
- Progress модулю.

---

# Ограничения

Модуль не должен:

- выполнять образовательную бизнес-логику;
- самостоятельно решать задания;
- хранить данные других доменов;
- изменять задачи без участия AI/Tasks модулей;
- напрямую обращаться к базе других модулей;
- обходить публичные интерфейсы модулей;
- создавать циклические зависимости.

---

# Архитектура

OCR является инфраструктурным модулем обработки входных данных.

Основной поток:

```

User  
|  
v  
Frontend  
|  
v  
OCR Module  
|  
+--> Image Processing  
|  
+--> OCR Engine  
|  
v  
Recognized Content  
|  
+--> Tasks Module  
|  
+--> AI Module

```

Пример сценария:

1. Пользователь загружает фотографию задания.
2. OCR принимает изображение.
3. Изображение сохраняется во временное хранилище.
4. OCR Engine распознаёт текст.
5. Результат очищается и структурируется.
6. AI анализирует распознанное задание.
7. Пользователь получает решение и объяснение.

# Компоненты

## Router

Назначение:

Предоставляет API для работы с OCR.

Ответственность:

- загрузка изображений;
- получение статуса обработки;
- получение результата распознавания.

Не содержит:

- OCR-логику;
- работу с AI;
- обработку текста.

---

## Service

Назначение:

Содержит бизнес-логику процесса распознавания.

Ответственность:

- запуск OCR процесса;
- управление состояниями обработки;
- взаимодействие с OCR Engine;
- обработка результата;
- проверка качества распознавания.

Основные действия:

```

create_ocr_job()

process_image()

recognize_text()

validate_result()

```

---

## Repository

Назначение:

Работа с данными OCR в базе.

Ответственность:

- создание OCR-записей;
- получение истории обработки;
- обновление статусов;
- сохранение результатов.

Не содержит:

- OCR алгоритмов;
- бизнес-правил.

---

Назначение:

Содержит:

- запросы;

- результаты распознавания.

---

## Models

Содержит:

# Бизнес-правила

- Один OCRJob относится только к одному изображению.
- Пользователь может видеть только свои результаты.
- OCR результат может использоваться AI только после успешной обработки.
- Неуспешные задачи могут быть повторены.
- Низкое качество распознавания должно быть отмечено.

---

# Инварианты

- OCRJob всегда имеет владельца.
- OCRJob всегда имеет статус.
- Завершённый OCRJob должен иметь OCRResult.
- Удаление пользователя не должно оставлять доступные OCR данные.
- OCR не изменяет исходное изображение.

# Безопасность

Описание:

- проверка владельца изображения;
- ограничение размера файлов;
- проверка типов файлов;
- защита от загрузки вредоносных файлов;
- аудит действий пользователя.

Не хранить:

- персональные данные в OCR результатах без необходимости;
- временные файлы после обработки.

# Логирование

Логируются:

- создание OCR задач;
- время обработки;
- ошибки OCR Engine;
- качество распознавания.

Не логируются:

- изображения пользователей;
- токены;
- пароли;
- персональные данные.

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- OCR Engine подключается через отдельный интерфейс.
- Новые форматы данных документируются.
- Изменение событий требует обновления Event Catalog.
