# Назначение

Модуль **Users** отвечает за хранение и управление информацией о пользователях платформы.

Модуль является единственным источником данных о пользователях и предоставляет другим модулям доступ к пользовательской информации через внутренние сервисы приложения.

Users отвечает только за управление сущностью пользователя и связанными с ней данными:

- профиль;
- настройки;
- роли;
- подписки;
- персональные данные.

Аутентификация, авторизация, JWT, Refresh Token и управление сессиями находятся в зоне ответственности модуля **Auth**.

---

# Зона ответственности

Модуль отвечает за:

- создание пользовательской сущности;
- хранение учетной записи пользователя;
- управление профилем пользователя;
- управление настройками пользователя;
- управление ролями;
- управление статусами пользователя;
- управление подпиской пользователя;
- хранение персональных данных;
- управление аватаром;
- предоставление информации о пользователях другим модулям.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- регистрацию пользователя через систему аутентификации;
- проверку пароля;
- выдачу JWT;
- управление Refresh Token;
- OAuth-провайдеры;
- подтверждение Email;
- восстановление пароля;
- управление пользовательскими сессиями;
- платежные операции;
- отправку уведомлений;
- историю обучения;
- результаты экзаменов;
- AI-рекомендации.

Эти задачи реализуются отдельными модулями.

---

# Ограничения

Модуль не должен:

- выполнять бизнес-логику других модулей;
- обращаться напрямую к AI;
- отправлять Email самостоятельно;
- выполнять платежные операции;
- хранить данные образовательного процесса;
- хранить результаты подготовки;
- изменять данные других доменов;
- обходить интерфейсы других модулей;
- создавать циклические зависимости.

# Компоненты

## Router

Назначение:

HTTP API интерфейс модуля.

Ответственность:

- обработка HTTP-запросов;
- получение данных пользователя из Auth context;
- вызов сервисного слоя;
- возврат DTO.

Не содержит:

- бизнес-логику;
- работу с БД.

---

## Service

Назначение:

Основной слой бизнес-логики Users.

Ответственность:

- изменение профиля;
- обновление настроек;
- изменение ролей;
- изменение статусов;
- управление подпиской;
- проверка бизнес-правил.

---

## Repository

Назначение:

Абстракция доступа к данным.

Ответственность:

- получение пользователей;
- создание пользователей;
- обновление данных;
- удаление пользователей;
- работа с ORM.

Не содержит бизнес-логики.

---

# Бизнес-правила

- Пользователь имеет только одну учетную запись.
- Email пользователя уникален.
- Пользователь имеет только одну основную роль.
- Пользователь может иметь только одну активную подписку.
- Профиль не может существовать без User.
- Настройки принадлежат только одному пользователю.
- Удаление пользователя выполняется через Soft Delete.
- Аватар хранится во внешнем Storage.
- Изменение роли доступно только администраторам.

---

# Инварианты

- User всегда имеет уникальный идентификатор.
- Email всегда уникален.
- User всегда имеет статус.
- User всегда имеет роль.
- Profile не существует без User.
- Settings принадлежат только одному User.
- Subscription принадлежит только одному User.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Все DTO описываются через Schemas.
- Все изменения БД сопровождаются миграциями.
- Все события обновляют Event Catalog.
- Запрещено обращаться к БД в обход Repository.
