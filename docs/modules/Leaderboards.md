# Назначение

Модуль **Leaderboards** отвечает за систему рейтингов и соревновательных механик внутри образовательной платформы.

Модуль предоставляет пользователям возможность сравнивать свои результаты подготовки с другими участниками через рейтинги, достижения и показатели активности.

Модуль покрывает:

- рейтинги пользователей;
- подсчёт очков;
- позиции в рейтингах;
- соревновательные механики;
- мотивационные показатели.

Leaderboards существует для повышения вовлечённости пользователей и поддержания регулярной подготовки к экзаменам.

---

# Зона ответственности

Модуль отвечает за:

- расчёт рейтингов пользователей;
- хранение лидербордов;
- обновление позиций пользователей;
- начисление рейтинговых очков;
- создание категорий рейтингов;
- предоставление пользовательских позиций;
- интеграцию с системой достижений.

---

# Что НЕ входит в ответственность

Модуль не отвечает за:

- определение качества знаний пользователя;
- анализ ошибок;
- создание учебного плана;
- хранение прогресса подготовки;
- генерацию заданий;
- обучение пользователя.

Модуль получает данные о действиях пользователя и преобразует их в рейтинговые показатели.

---

# Ограничения

Модуль не должен:

- самостоятельно изменять прогресс пользователя;
- хранить учебные результаты как источник истины;
- определять сложность заданий;
- влиять на AI-рекомендации;
- содержать бизнес-логику других доменов;
- создавать циклические зависимости.

---

# Архитектура

Leaderboards является отдельным доменным модулем, который получает события активности пользователя.

Основной поток:

```

Tasks Module  
|  
v  
TaskCompleted Event  
|  
v  
Leaderboards  
|  
v  
Update Score  
|  
v  
Leaderboard Ranking  
|  
v  
Frontend

```

Пример:

```

Пользователь решил 10 заданий  
|  
v  
Progress отправляет событие  
|  
v  
Leaderboards начисляет очки  
|  
v  
Обновляется позиция

```

# Компоненты

## Router

Назначение:

Предоставляет API для получения рейтингов.

Ответственность:

- получение лидербордов;
- получение позиции пользователя;
- получение статистики рейтинга.

Не содержит:

- расчёт очков;
- правила рейтинга.

---

## Service

Назначение:

Содержит бизнес-логику рейтингов.

Ответственность:

- начисление очков;
- обновление позиции;
- пересчёт рейтинга;
- формирование рейтингов.

Основные методы:

```

calculate_score()

update_ranking()

get_leaderboard()

get_user_position()

```

---

## Repository

Назначение:

Работа с данными рейтингов.

Ответственность:

- сохранение очков;
- получение рейтингов;
- сортировка пользователей;
- обновление позиций.

---

## Schemas

Назначение:

Описание DTO.

Содержит:

- рейтинг пользователя;
- список лидеров;
- статистику.

---

## Models

Назначение:

Описание ORM моделей.

Содержит:

- Leaderboard;
- UserScore;
- RankingPeriod.

---

## Validators

Назначение:

Проверка данных рейтинга.

Ответственность:

- проверка типа рейтинга;
- проверка корректности очков;
- проверка периода рейтинга.

---

## Permissions

Назначение:

Контроль доступа.

Ответственность:

- пользователь получает собственную позицию;

# Бизнес-правила

- Очки начисляются только за подтверждённые действия.
- Пользователь не может изменить свой рейтинг напрямую.
- Рейтинг должен быть воспроизводимым.
- Все изменения рейтинга должны иметь источник.
- Администратор может изменять правила рейтинга.

---

# Инварианты

- UserScore всегда принадлежит пользователю.
- UserScore всегда связан с Leaderboard.
- Очки не могут быть отрицательными.
- Один пользователь имеет одну позицию в конкретном рейтинге.
- Позиция соответствует текущему количеству очков.

# Правила разработки

- Router не содержит бизнес-логики.
- Service содержит бизнес-логику.
- Repository работает только с данными.
- Рейтинг рассчитывается только через сервис.
- Все источники очков должны быть задокументированы.
- Изменение событий требует обновления Event Catalog.
